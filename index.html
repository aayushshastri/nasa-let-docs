    NASA LET Test Bed - Technical Documentation¶

    Abstract¶

    The NASA Lab Evaluation Test Bed (LET) project provides a fully Python-based replacement for traditional DAQ control and monitoring systems. It combines NI-DAQmx interfacing, socket communication, PyVISA instrument control, and structured data logging into a unified, modular, open-source framework. The LET Test Bed is designed to provide scalable, replicable, and cost-effective hardware-software solutions for laboratory environments.

    Background¶

    Traditional data acquisition (DAQ) platforms often rely on closed-source software environments like LabVIEW, creating barriers related to cost, licensing, flexibility, and scalability. Additionally, many legacy systems are difficult to maintain and lack direct integration with modern open-source ecosystems.

    This project addresses these challenges by building a fully open, Python-based alternative that: - Interfaces directly with DAQ hardware (NI devices) via NI-DAQmx Python API. - Supports VISA-compatible laboratory instruments through PyVISA. - Implements real-time communication via TCP/IP sockets. - Provides modular, extensible Python modules for acquisition, monitoring, and control.

    Problem Statement¶

    There is a critical need for an open-source, Python-driven DAQ control architecture that can replace or augment existing proprietary systems while maintaining real-time performance, modularity, and ease of customization.

    The system must meet the following requirements: - Continuous, high-fidelity data acquisition from multiple analog channels. - Seamless communication between acquisition subsystems and external GUIs or controllers. - Flexible configuration via standard file formats (e.g., Excel). - Clear, documented API to allow easy extension and integration.

    Project Objectives¶

    • Develop a scalable Python-based DAQ acquisition platform using NI-DAQmx.
    • Integrate VISA device communication for laboratory hardware.
    • Implement robust socket-based interprocess communication between DAQ and GUI systems.
    • Structure the project into independent, reusable Python modules with clear documentation.
    • Provide detailed technical documentation and setup guidelines for future extensibility.

    System Overview¶

    The system architecture consists of four primary modules:

    1. DAQ Acquisition Module (readall.py, setupDAQ.py):
    2. Handles multi-channel analog input configuration, timing, and data acquisition.
    3. Supports continuous sampling at user-defined rates.

    4. Saves structured output (CSV files) for analysis.

    5. Instrument Communication Module (pyvisaTest.py):

    6. Controls external lab equipment via PyVISA.

    7. Sends SCPI commands, reads responses, and configures devices programmatically.

    8. Socket Communication Layer (socket_comms.py):

    9. Enables real-time communication between the DAQ subsystem and external GUIs or processing applications.

    10. Allows flexible deployment across distributed systems.

    11. Data Processing and Utilities (calculations.py, hardware.py):

    12. Provides statistical analysis functions (e.g., RMS, mean, standard deviation).
    13. Defines object-oriented sensor abstraction for scalable channel configuration.

    The system is highly modular, allowing new sensors, instruments, or communication endpoints to be integrated with minimal codebase disruption.

    Hardware and Interfaces¶

    • DAQ Hardware: National Instruments DAQ devices supporting NI-DAQmx driver.
    • Instruments: VISA-compatible laboratory equipment (oscilloscopes, power meters, etc.)
    • Communication Protocols: TCP/IP sockets, GPIB/USB/VISA standards.
    • Configuration Sources: Excel spreadsheets for dynamic hardware mapping.

    Software Modules¶

    Module Description
    readall.py Multi-channel data acquisition script with automatic
    channel detection.
    setupDAQ.py DAQ task configuration including sampling rates and
    clock settings.
    pyvisaTest.py Instrument communication module using PyVISA for
    SCPI-based devices.
    socket_comms.py TCP server for real-time inter-process
    communication.
    calculations.py Post-acquisition data analytics (RMS, standard
    deviation, peak-to-peak).
    hardware.py Object-oriented sensor abstraction for structured device
    management.
